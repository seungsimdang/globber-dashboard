# 사용량 운영 기억

에이전트 위임·문서 탐색·검증 전에 적용한다. Claude·Codex의 영구 프로젝트 기억이며, 개인 홈 메모리나 서버 사용량 정산 자료를 뜻하지 않는다.

## 2026-10-28 사용자 피드백

아래 수치는 사용자가 제공한 로그 집계다. 이 작업에서 원본 로그를 재검증하지 않았다.

- F1 작업의 17:18~17:33 약 15분 동안 5시간 사용량 표시가 54%에서 94%로 40%p 증가했다.
- 상속 대화를 제외하고 실제 token_usage_record를 응답 ID로 중복 제거한 집계: 메인 80회/입력 1,073만, 구현자 75회/1,352만, 추가 QA 29회/504만, guardian 21회/90만, 총 205회/3,019만 토큰이다.
- 캐시 입력 약 2,923만, 새 입력 약 96만이다. 누적 입력은 호출마다 재처리된 문맥의 합이며 한도 소모율로 환산할 수 없다. 에이전트별 정확한 %p는 서버 정산 자료가 없어 확인되지 않았다.
- 구현자·QA 모두 전체 대화를 상속했고 첫 입력이 각각 약 9.4만·15.1만 토큰이었다. 메인은 위임 중에도 중복 탐색·검토·지시를 계속했다(메시지 전달 14회, 도구 묶음 51회, 평균 입력 13.4만).
- 과거 handoff 일괄 출력, 긴 규칙·소스 재열람, Task Team 스킬 전체 출력 2회가 있었다. 메인 도구 출력 약 34만 자, 입력 문맥 약 3.5만→18.2만 토큰으로 증가했다.
- 전체 Vitest는 메인 3회·구현자 2회·QA 1회로 총 6회였다. 추가 QA는 사전 보고 없이 실행됐다. QA 시작 전에도 표시 사용량은 54%→72%로 증가했다.
- 운영상 원인은 전체 문맥 상속, 위임과 중복되는 메인 탐색, 넓은 읽기·재열람, 검증 중복 및 사전 보고 없는 QA 추가다. 캐시 적중률만으로 이 비용을 무시하지 않는다.

## 행동 규칙

1. Codex는 `fork_turns: "none"`을 명시하고 필요한 결정·경로·담당 범위만 전달한다. 위임문은 6,000자 이내로 쓴다. 작은 작업을 이유 없이 여러 에이전트로 나누지 않는다.
2. Codex 메인은 위임 중 담당 경로를 다시 읽거나 검증하지 않는다. 반환 후 검토에 집중한다. 추가 지시는 발견·결정이 생겼을 때 모아 보낸다.
3. 두 도구 모두 필요한 파일·범위만 읽는다. 과거 인계 문서 일괄 출력, 변경 없는 동일 범위 재열람을 피한다. 큰 출력은 파일·행 범위를 줄인다. 필수 규칙의 최초 읽기를 생략하지 않는다.
4. Codex 검증은 필요한 완료 후·병합 후 시점에 모은다. 성공한 검사는 파일 상태가 같으면 반복하지 않는다. 실패·변경·병합 후에는 다시 검증할 수 있다. QA 등 추가 에이전트는 실행 전에 이유·범위·검증 시점을 보고한다. 보고를 사용자 승인으로 간주하지 않는다.

## 훅 제거

2026-11-11 사용자 요청으로 Claude·Codex의 사용량 가드 훅 등록과 `.harness/usage_guard.py` 실행 코드를 모두 제거했다. 위 행동 규칙은 문서 지침으로 유지하며 훅으로 강제하지 않는다. `USAGE_PLAN` 표식과 `사용량 검증 단계` 보고 형식도 더 이상 요구하지 않는다.

제거 확인용 테스트와 과거 검증 산출물도 정리했다. 과거 구현·검증 내용은 Git 이력으로 확인한다.
