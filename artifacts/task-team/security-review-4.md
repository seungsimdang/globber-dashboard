# T08 보안 리뷰 4 - 사이클 최종

## 판정

**보안 통과.** 현재 미해결 Critical/High/Medium/Low 취약점은 없다. 이번 QA 보완 전의 좌표 강제 변환 문제는 Low 심각도의 입력 검증 결함이었으며, 코드 수정으로 해소됐다. 기존 사용자 수용 개발 HTTP 계약은 조건부 잔여 위험으로 유지한다.

이 보고서는 [security-review-3.md](security-review-3.md)의 인증·인가, 서버 분리, 입력 검증, 시크릿, 외부 호출 검토를 재사용하고 지정된 변경만 재검토했다. 코드 변경이나 테스트 실행은 하지 않았다.

## 이번 변경 검토

### F1 (Low, 해소) 외부 좌표 문자열의 숫자 강제 변환

- 이전 동작은 `Number()` 전에 자료형을 확인하지 않아 `null`, 빈 문자열, 불리언, 배열 같은 잘못된 좌표를 숫자로 바꾸고 범위 안 값이면 후보로 반환할 수 있었다. QA 기록은 이 입력으로 200 후보가 나오는 실패를 재현했다.
- 현재 `toCandidate`는 `lat`/`lon`이 number 또는 비어 있지 않은 문자열인지 먼저 확인하고, 그 다음 숫자 변환·유한성·범위 검사를 한다. 정상 숫자 `0`과 숫자로 표현된 문자열은 유지된다 (`src/lib/server/geocode.ts:36-48`). 이 변경은 신뢰할 수 없는 상류 응답의 좌표 검증을 강화하며, 새 우회 경로를 만들지 않는다.
- QA 전달 결과: 잘못된 좌표 경우를 확인한 뒤 보완된 단독 14개 테스트가 통과했다. 테스트 파일은 읽거나 실행하지 않았다. 구현 기록이 가리키는 `artifacts/task-team/qa-report-2.md`는 이 리뷰 시점에 저장소에서 찾지 못했으므로, 테스트 결과는 독립 검증이 아닌 QA 전달 근거로 기록한다.

## triage-4 판정 재검토

- **운영 URL 중복 — SKIP 타당.** triage는 기존 확인 기록의 성공 경로 및 `api-spec.md` 2-B와 구현의 고정 경로 조합이 일치한다고 판단했다. 이 최종 리뷰에서 실서버 요청은 재실행하지 않았다. 경로가 환경 설정에 따라 잘못될 가능성은 기능 설정 문제이며, 클라이언트가 호스트·스킴·경로를 지정하지 않아 SSRF 또는 권한 우회 근거는 없다 (`src/lib/server/cityUpstream.ts:91-109`).
- **모달 중 탭 전환 — SKIP 타당.** triage에 기록된 Radix modal의 포커스 트랩·외부 포인터 차단 근거로 일반 사용자 탭 전환 경로가 차단된다. 강제 이벤트 호출은 사용자 경로로 보지 않는다는 triage 판단을 수용했다. 별도 보안 finding은 없다. 운영 쓰기는 서버에서도 계속 거부된다 (`src/lib/server/cityServer.ts:27-39`).
- triage의 보안 절은 차단 finding이 없고 HTTP 개발 상류는 사용자 지정 계약의 조건부 위험이라고 기록했다. 이전 보안 리뷰의 결론과 일치한다.

## 구현 기록 판정

- `implementation-6.md`의 Codex QA 보완 좌표 입력 항목: **타당**. 잘못된 upstream 좌표가 `Number()` 강제 변환으로 유효 범위 숫자가 될 수 있었다. 새 선행 가드가 해당 비숫자 타입과 빈 문자열을 제외하며, 이후 범위 검증은 유지된다 (`src/lib/server/geocode.ts:36-48`). 테스트 결과는 위의 QA 전달 근거와 동일하다.
- `implementation-3~6.md`의 기존 권한·정보 노출·입력 검증 관련 항목별 판정은 `security-review-3.md`에 기록되어 있고, 이번 변경으로 달라진 부분 외에는 재탐색하지 않았다.

## 잔여 위험 및 증거 구분

- **수용된 조건부 위험 (Low): 개발 상류 HTTP 전송.** 요구사항 2차 계약이 개발 상류를 HTTP 기반으로 지정하고 코드는 HTTP/HTTPS를 모두 허용한다. 실제 환경 변수와 네트워크 경로는 확인하지 않았다. 배포 설정이 평문 HTTP라면 경로상 관찰자가 개발 토큰을 얻거나 개발 쓰기 요청을 조작할 수 있다. 운영 쓰기는 별도 403 가드가 있다. 이 위험은 사용자 수용 계약이며 새 코드 finding이나 이번 재작업 사유로 분류하지 않는다. 가능하면 TLS 또는 신뢰된 사설 네트워크를 사용한다.
- **정적 소스 근거:** 변경 diff와 기존 보안 리뷰 결과를 확인했다. 좌표 가드가 변환 전 잘못된 자료형·빈 문자열을 차단함을 확인했다.
- **테스트 근거:** QA가 단독 14개 테스트 통과를 전달했다. 이 리뷰에서는 테스트 코드·QA 보고서를 열거나 실행하지 않았다.
- **실서버·배포 근거:** 이번 리뷰에서 호출하지 않았고 실제 환경 변수도 읽지 않았다. 따라서 개발 전송의 현재 TLS 여부, 실제 배포 동작은 확인하지 못했다.

## 최종

**사이클 보안 게이트 승인.** 새 좌표 입력 검증 변경은 정적으로 타당하고 QA 통과 결과가 전달되었다. 차단 취약점은 없으며, 이 승인은 전체 QA 완료나 실제 배포 검증을 의미하지 않는다.
