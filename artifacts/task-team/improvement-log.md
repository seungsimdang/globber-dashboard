# 개선 기록: 실제 도시 API 연동 사이클

| 관찰 | 영향 | 개선 |
| --- | --- | --- |
| 구현자 2명이 5시간 사용량 한도로 중간 종료 | 재개 메시지로 이어서 완료, 작업 손실 없음 | 병렬 구현 전 남은 한도를 고려해 범위를 나눈다 |
| 리뷰어(읽기 위주)도 Bash·Write가 있어 `require-isolation-when-dirty` 훅이 worktree 격리를 강제 | 리뷰 전 커밋, 리뷰 파일을 worktree에서 회수하는 단계 추가 | 오케스트레이터 9번의 "별도 worktree 없이 진행"과 훅 동작이 어긋난다. 하네스 점검 시 둘 중 하나로 맞춘다 |
| 메인 체크아웃에서 lint가 `.claude/worktrees/`를 스캔해 4,669건 오탐 | 병합 직후 worktree를 지우기 전까지 lint 결과가 무의미 | eslint 설정의 ignore에 `.claude/worktrees/**` 추가를 검토한다(vitest는 이미 제외) |
| 여러 커밋을 한 Bash 호출에 묶어 커밋 메시지 훅이 차단 | 재실행 1회 | 커밋은 호출당 1개 |
| `pnpm-workspace.yaml`을 존재 확인 없이 덮어씀 | 즉시 원복, 영향 없음 | 쓰기 전 `git ls-files`나 Read로 존재를 확인한다 |
| 미검증 항목을 보고에 남겼다가 훅 지적으로 로컬 서버·브라우저 검증 추가 | 가상 스크롤·실데이터 조회·번들 검사를 사이클 안에서 확인 | 읽기 전용으로 확인 가능한 항목은 보고 전에 직접 검증한다 |
| 진행 메시지를 영어로 작성해 한국어 훅이 반복 차단 | 재보고 반복 | 사용자에게 보이는 모든 문장은 한국어로 쓴다 |
| 질문 창 직접 입력이 지시형이어도 `block-reask-after-free-text-answer.sh`가 같은 응답의 위임을 차단 | 결정 반영이 한 턴 늦어짐 | 질문형 직접 입력만 차단하도록 수정(`855c33c`, `Harness-Scope: generic`) |
| `require-answer-before-edit.sh`의 haiku 판정이 이미 기록된 답변을 미답변으로 판정 | amend·push가 한 턴 늦어짐. 차단을 확정으로 받아들여 작업을 미룸 | 오판이 의심되면 답변을 보강해 한 번 더 시도한다. 판정 입력·출력 기록이 없어 원인 확인 불가 |
| 공용 하네스 수정을 seungness 직접 커밋으로 처리 | 불필요한 브랜치 생성 후 삭제 | 프로젝트에서 `Harness-Scope: generic`으로 커밋하면 통합 브랜치 병합 뒤 자동 전달된다(`docs/agent-harness/sync.md`) |
