## 2. 결과 수 표시와 검색

### 2.1 결과 수 줄 (신규)

- 위치: `SearchInput` 줄 오른쪽 끝(`SearchInput`은 `max-w-sm` 유지, 같은 줄에서 양 끝 정렬). 1024px에서 한 줄에 들어간다.
- 문구(`text-sm text-gray-500`, 숫자는 천 단위 구분 쉼표):
  - 검색어 없음: `전체 3,791개` (2차: 서버 이름 접두사가 붙는다. 2-F 참조.)
  - 검색어 있음: `검색 결과 12개 / 전체 3,791개`
  - 검색 결과 0건: `검색 결과 0개 / 전체 3,791개` (표 안에는 기존 "'{검색어}'에 대한 검색 결과가 없습니다." 유지)
- 로딩 중·에러 상태에서는 결과 수 줄을 숨긴다(자리는 비워두지 않아도 됨).
- 접근성: 이 줄을 `aria-live="polite"`로 두어 필터링 결과를 스크린리더에 알린다. 20개 제한 안내는 B-1 결정으로 필요 없으므로 만들지 않는다.
- 도시 추가·삭제 직후 숫자가 목록 갱신과 함께 즉시 바뀐다.

### 2.2 검색 규칙

| 항목 | 규칙 |

- 폼 안에서 국기 미리보기는 추가하지 않는다(현재 없음).
- 목록: 국가코드 열은 `ARE`처럼 alpha-3를 그대로 표시한다. 도시명 앞 국기는 alpha-3로 계산한다. 63개 코드 전부 매핑(B-4)이 목표이며, 매핑에 없는 코드는 `🏳️`로 표시해 목록이 깨지지 않는다. 형식은 유효하지만 매핑에 없는 코드로도 등록은 막지 않는다(기존 원칙).

## 4. 100자 제한 제거 (B-5)

- 도시명·국가명 입력의 `maxLength=100` 속성과 "~자 이하여야 합니다" 오류 문구를 제거한다.
- 검증은 필수 입력(공백 제외 1자 이상)만 남긴다. 오류 문구 `도시명을 입력해주세요`, `국가명을 입력해주세요` 유지.
- 서버가 길이 제한을 두면 400 메시지를 §5.2 방식으로 표시한다. 서버 제한 값은 확인 필요이므로 문서·UI에 숫자를 쓰지 않는다.
- 매우 긴 이름이 표에서 레이아웃을 깨지 않도록 도시명·국가명 셀은 줄바꿈 허용(`break-words`)으로 처리한다. 행 높이만 늘어난다.

### 5.1 클라이언트 중복 사전 검사 (B-6)

- 시점: 제출 시, 필드 검증이 모두 통과한 뒤 서버 요청 전에 실행. 요청은 보내지 않는다(제출 버튼은 눌렀다 바로 복귀, 로딩 표시 없음).
- 비교: 도시명+국가명 쌍, 앞뒤 공백 제거 후 대소문자 무시. 수정 모드는 편집 중인 도시 자신을 제외한다. 서버의 비교 기준(공백·대소문자)은 확인 필요이므로 클라이언트는 위 기준으로만 막고, 통과해도 서버가 거부하면 §5.2로 표시한다.
- 표시: 폼 상단 `FormErrorBanner`(기존 `role="alert"` 배너)에 `이미 등록된 도시입니다.`, 도시명·국가명 입력 두 개의 테두리를 오류 색으로 강조(현재 중복 처리 방식과 동일). 입력값은 보존된다. (2차: 중복 사전 검사 대상은 개발 탭 목록이다. 운영 탭은 쓰기 불가.)
- 목록을 아직 못 받았거나 조회 실패 상태이면 사전 검사를 건너뛰고 서버 판단에 맡긴다.
- 배너와 강조는 도시명 또는 국가명 입력이 바뀌면 해제하지 않아도 되며 다음 제출 시 다시 계산된다(현재 동작과 동일).

### 5.2 쓰기 실패 (추가·수정)

- 모달은 닫히지 않고 입력값을 전부 보존한다. 제출 버튼은 요청 종료 후 즉시 다시 활성화된다(재시도 가능). 모달 닫기(Esc, 배경, 취소)는 요청 중에는 막힌 현재 동작 유지.
- 표시 위치: 모두 폼 상단 `FormErrorBanner`. 필드 하단 인라인 오류는 클라이언트 검증 전용으로 유지한다.
- 서버 400 `{status:"fail", data:"메시지"}`: 메시지 문자열을 그대로 배너에 표시한다(가공하지 않음). 서버가 중복을 거부한 경우도 같은 방식이며 이때 도시명·국가명 강조는 메시지가 `이미 등록된 도시입니다.`와 같을 때만 적용한다. 서버 중복 응답의 상태 코드·문구는 확인 필요.
- 그 외 원인별 문구:

| 원인 | 배너 문구 |
| --- | --- |
| 네트워크 실패, 타임아웃 | `서버에 연결할 수 없습니다. 입력한 내용은 유지됩니다. 잠시 후 다시 시도해주세요.` |
| 서버 5xx | `서버에 문제가 발생했습니다. 입력한 내용은 유지됩니다. 잠시 후 다시 시도해주세요.` |
| 토큰 발급 실패, 재발급 후에도 401 | `서버 인증에 실패했습니다. 잠시 후 다시 시도하거나 관리자에게 문의해주세요.` |
| 서버 설정 오류(테스트 이메일 등 환경 변수 없음) | `서버 설정이 올바르지 않아 저장할 수 없습니다. 관리자에게 문의해주세요.` |
| 서버가 메시지 없이 4xx | `저장하지 못했습니다. 입력 내용을 확인해주세요.` |

- 토큰 값, 테스트 이메일, API 주소는 어떤 문구에도 넣지 않는다.
- 수정 대상이 서버에 없음: 현재 동작 유지(모달 닫기 + 토스트 `대상을 찾을 수 없습니다.` + 목록 재조회). 서버가 없는 id에 어떤 상태·메시지를 반환하는지 확인 필요이므로, 4xx 중 이 경우로 판별되는 기준은 T04에서 정한다. 판별되지 않으면 위 "메시지 없이 4xx" 또는 서버 메시지 배너로 처리한다.
- 배너 문구는 새 에러가 올 때 교체되며, 다음 제출 시작 시 지운다(현재 동작).

### 5.3 삭제 실패

모달 없이 토스트(`variant: "error"`)로 표시한다. 대상 없음일 때만 다이얼로그를 닫고 목록을 재조회하고, 그 외 원인은 다이얼로그를 열어 둔 채 재시도할 수 있게 한다(게이트 결정).

| 원인 | 토스트 제목 |
| --- | --- |
| 이미 삭제됨(대상 없음) | `대상을 찾을 수 없습니다.` (확인 필요: 서버의 없는 id 응답) |
| 네트워크 실패 | `서버에 연결할 수 없습니다. 잠시 후 다시 시도해주세요.` |
| 서버 5xx | `서버에 문제가 발생했습니다. 잠시 후 다시 시도해주세요.` |
| 토큰 발급 실패 | `서버 인증에 실패했습니다. 잠시 후 다시 시도하거나 관리자에게 문의해주세요.` |
| 서버 메시지가 있는 4xx | 서버 메시지 그대로 |

네트워크·5xx·인증·서버 설정 오류는 삭제 대상이 실제로 남아 있으므로 다이얼로그를 열어 둔다.

## 6. 접근성·반응형 변경분

- 결과 수 줄: `aria-live="polite"` (§2.1).
- 서버 오류 배너는 기존 `role="alert"` 유지.
- 반응형: 1024px 이상 기준 유지. 결과 수 줄은 좁은 폭(<768px)에서 검색창 아래 줄로 내려가도 된다(`flex-wrap`). 그 외 변경 없음.

## 7. 확인 필요 (서버 동작 미확인)

1. 중복 도시 추가 시 서버의 상태 코드·메시지 (§5.1, §5.2)
2. 없는 id 수정·삭제 시 서버의 상태 코드·메시지 (§5.2, §5.3)
3. 도시명·국가명 길이 제한 유무와 400 메시지 (§4)
4. 존재하지 않는 alpha-3 코드에 대한 서버 검증 여부 (§3)
5. 서버의 중복 비교 기준(공백·대소문자) (§5.1)
6. 3,791행 렌더링 실측 성능 (§1.1, T05 이후 판단)

## 2-E. 운영 탭: 쓰기 버튼 비활성과 안내

대상 버튼: 헤더 `도시 추가`, 행의 수정(연필)·삭제(휴지통) 아이콘 버튼. 빈 목록의 `도시 추가` 버튼은 아래 결정으로 제거한다.

- 비활성 표현: 기존 `Button`의 비활성 스타일(`disabled:opacity-40 disabled:pointer-events-none`)을 그대로 쓴다. 새 색·스타일 없음. 전부 `disabled`(네이티브)로 처리해 키보드 탭 순서에서 빠지고 클릭·Enter가 동작하지 않는다.
- 안내 문구 위치: 탭 목록 바로 아래, 검색 줄 위의 한 줄.
  - 스타일: `flex items-center gap-2 rounded-lg bg-amber-50 px-4 py-2 text-sm text-amber-800`, 왼쪽에 `Info`(lucide, `h-4 w-4`, `aria-hidden`) 아이콘. 개발 탭에서는 렌더하지 않는다(자리도 비운다).
  - 문구: `운영 서버는 쓰기 인증 준비 전이라 조회만 할 수 있습니다.`
- 접근성
  - 안내 줄에 고정 `id`를 주고, 헤더 `도시 추가` 버튼과 행의 수정·삭제 버튼에 `aria-describedby`로 연결한다. 이렇게 하면 스크린리더가 버튼에 도달할 때 비활성 사유를 읽는다.
  - 네이티브 `disabled`는 포커스를 받지 못하므로 스크린리더의 가상 커서(탐색 모드)로 읽는 경로가 사유 전달 수단이다. 키보드 포커스로도 사유를 알리려면 `aria-disabled`(포커스 가능, 클릭 무시) 방식이 필요하나, 현재 `Button` 공용 컴포넌트에 없는 동작이라 이번엔 네이티브 `disabled` + `aria-describedby` + 보이는 안내 줄로 정한다. 변경 필요 시 사용자 결정 항목에 둔다(2-I 1번).
  - 안내 줄은 탭 전환 시 나타나고 사라진다. 전환 자체를 알리기 위해 `role`/`aria-live`는 달지 않는다(탭 선택 변경과 패널 내용이 이미 전달됨).
- 툴팁(hover 안내)은 추가하지 않는다. 비활성 버튼은 포인터 이벤트가 없어 동작하지 않으며, 보이는 안내 줄로 충분하다.
- 빈 목록 상태(두 탭 공통): 빈 목록 안내 속 `도시 추가` 버튼과 `CityListTable`의 `onAddCity` prop을 제거하고 문구만 표시한다. 헤더 버튼과 같은 `openAddModal`을 호출하는 중복 버튼이라 사용자 결정으로 삭제(1차 §2 빈 상태 버튼 대체).

| 탭 | 선택된 탭 라벨 + 밑줄(2-D) |
| 목록 헤더 건수 줄 (1차 §2.1) | 서버 이름을 앞에 붙인다. 검색어 없음: `운영 서버 전체 4,204개` / `개발 서버 전체 3,791개`. 검색어 있음: `운영 서버 검색 결과 12개 / 전체 4,204개`. 0건: `운영 서버 검색 결과 0개 / 전체 4,204개`. 숫자는 천 단위 쉼표, 스타일 1차 그대로(`text-sm text-gray-500`, `aria-live="polite"`) |

| 삭제 확인 다이얼로그 | 제목 `[개발] 도시 삭제`. 본문 첫머리에 `개발 서버에서` 를 넣어 `개발 서버에서 '{도시명}'을(를) 삭제하시겠습니까?` 형태로 쓴다(기존 본문 문구는 구현에서 확인해 같은 구조로 앞에 붙임) |
| 성공 토스트 | `개발 서버에 도시가 추가되었습니다` / `개발 서버의 도시가 수정되었습니다` / `개발 서버에서 도시가 삭제되었습니다` |
| 오류 메시지 | 모달 배너·삭제 토스트의 1차 §5.2/§5.3 문구는 그대로 두되 대상 서버는 모달 제목과 다이얼로그에서 이미 식별되므로 접두사를 추가하지 않는다. 단 서버 설정 오류 문구는 아래 2-G를 따른다 |

서버 이름 접두사의 시각 구분은 텍스트로만 한다(배지·색 구분 추가 없음).

## 2-G. 탭별 상태 (로딩·오류·설정 오류)

각 탭의 상태는 독립이다. 한 탭이 오류여도 다른 탭 전환·표시는 정상이다. 상태는 표 컨테이너 안에 1차 구조 그대로 표시한다.

| 상태 | 표시 |
| --- | --- |
| 로딩 (해당 탭 최초 조회) | `{서버} 서버 목록을 불러오는 중...` (1차 `불러오는 중...`에 서버 이름 추가). 건수 줄 숨김 |
| 이미 받은 탭으로 복귀 | 캐시된 목록을 즉시 표시. 재조회가 일어나도 `불러오는 중...`으로 바꾸지 않고 기존 행 유지(1차 §5.0 "쓰기 후 갱신" 규칙과 동일) |
| 탭 전환 중 이전 탭 응답 | 현재 탭 표시에 영향 없음(캐시가 탭별 분리) |
| 일반 오류 (네트워크·5xx 등) | 1차 §5.0 사유 문구 앞에 서버 이름 한 줄을 붙인다. 예: `운영 서버: 서버에 연결할 수 없습니다. 네트워크 상태를 확인한 뒤 다시 시도해주세요.` + `다시 시도` 버튼(해당 탭만 재조회) |
| 설정 오류 (해당 서버의 주소 환경 변수 누락·오류) | 같은 오류 구조(아이콘+문구+`다시 시도`)로 `{서버} 서버 설정이 올바르지 않아 목록을 불러올 수 없습니다. 관리자에게 문의해주세요.` 환경 변수 이름·주소·토큰은 문구에 넣지 않는다. 건수 줄 숨김 |
| 개발 쓰기 설정 오류 (테스트 이메일 누락 등) | 조회는 정상이므로 목록은 그대로. 쓰기 시도 시 1차 §5.2 `서버 설정이 올바르지 않아 저장할 수 없습니다. 관리자에게 문의해주세요.` 배너를 모달에 표시 |
| 운영 쓰기 서버 거부 (우회 호출) | UI에서는 발생하지 않는다. 표시 문구는 운영 쓰기 안내 문구와 동일 |
| 두 탭 모두 설정 오류 | 각 탭에서 위 설정 오류 표시. 앱은 정상 렌더 |

설정 오류 문구는 `src/utils/cityErrorMessage.ts`에서 서버 이름을 받아 만든다(1차 원칙: 문구는 한곳에서).

## 2-H. 상태 전환 요약

4. 모달 안에서 쓰는 서버는 항상 열 때의 탭이다(운영에서는 열 수 없음).

## 3-A. 건수 줄 문구 (I-01)

| 상태 | 문구 |
| --- | --- |
| 검색어 없음 | `전체 4,204개` |
| 검색어 있음 | `검색 결과 12개 / 전체 4,204개` |
| 검색 결과 0건 | 기존 동작 유지(현재 `showCount` 조건 불변). 문구만 위 형식 |

## 3-B. 국가 검색 선택 컴포넌트 (I-02, I-03)

### 위치와 구성

- 모달 필드 순서: 도시명 -> 국가명(검색 선택) -> 국가코드(읽기 전용 표시) -> 위치 찾기 영역 -> 위도·경도 -> 버튼.
- 기존 "국가명" 자유 입력칸과 "국가코드" 입력칸은 없어진다(N-2). 라벨 `국가명`(필수 표시 유지)이 달린 검색 입력 하나가 둘을 함께 채운다.
- 컴포넌트 이름 제안: `CountryCombobox`(`src/components/cities/`, 국가 목록이 도메인 데이터). 입력은 `common/Input`, 라벨은 `common/Label` 재사용.
- 국가코드 표시: 국가가 선택되면 입력 아래 읽기 전용 텍스트 `국가코드 KOR`(`text-sm text-gray-500`, 코드는 `font-medium text-gray-900`). 미선택이면 표시하지 않는다. 입력 가능한 칸이 아니므로 `Input`을 쓰지 않는다.

### 공용 컴포넌트·Radix 선택 근거

- `src/components/common/`에서 확인한 파일: AlertDialog, Button, Dialog, Input, Label, LogoutButton, Tabs, Toast. 콤보박스·Select·Popover는 없다.
- Radix `Select`는 타이핑 필터링이 없는 선택 전용이라 "일부 입력 -> 후보 축소"(I-03)에 맞지 않는다. Radix에 Combobox primitive는 없다(일반 지식, 미확인).
- 결정: 기존 `Input` + 목록을 입력 바로 아래 같은 Dialog DOM 안에 인라인(absolute, `z-10`, `max-h-60 overflow-y-auto`)으로 그리고, ARIA combobox 패턴(`role="combobox"` 입력 + `role="listbox"` 목록)을 직접 적용한다. 새 의존성 없음, 승인 불필요.
- 인라인 이유: `Dialog`는 포커스 트랩과 Esc 닫기를 가진다. Popover를 포털로 띄우면 Dialog의 포커스 트랩·바깥 클릭 감지와 충돌할 수 있다. 단 `Dialog` content의 `overflow-y-auto`가 목록을 잘라낼 수 있으므로 국가 필드는 모달 상단부(도시명 바로 아래)에 두고, 구현자는 1024x768에서 목록이 잘리지 않는지 확인한다. 잘리면 `radix-ui`의 Popover(Anchor, 비모달)로 대체한다. 이 경우도 새 의존성은 아니다.

### 표시 형식

- 목록 항목(한 줄): 국가명 + 오른쪽 정렬 코드(예: `대한민국   KOR`). 국가명 `text-sm text-gray-900`, 코드 `text-xs text-gray-500`.
- 국기 이모지는 넣지 않는다. 3-6이 "국기 표시 추가"를 범위 밖으로 정했다. 요청 예시(국기+국가명+코드)와 다르므로 3-H D-1에서 확인한다.
- 선택된 상태의 입력값은 국가명만(예: `대한민국`). 코드는 아래 읽기 전용 줄에 있다.
- 일치 부분 강조는 하지 않는다.
- 목록 원천(N-1): ISO alpha-3 표(`countryFlagMapping.ts`의 키) x `Intl.DisplayNames(['ko'], {type:'region'})`. 기존 서버 데이터의 국가명은 원천으로 쓰지 않는다. `Intl`이 코드 문자열 자체를 돌려주는 코드는 목록에서 제외한다(I-02 edge의 두 안 중 "제외" 선택: 코드만 있는 행은 국가를 알아볼 수 없다).
- 정렬: 한국어 국가명 가나다순.

### 검색 동작

- 입력 변경 시 국가명 부분 일치(공백 제거 후 비교) 또는 코드 부분 일치(대소문자 무시)로 필터링한다. 입력이 비어 있으면 전체 목록을 가나다순으로 보여 준다.
- 포커스 시 또는 아래 방향키 시 목록을 연다. 입력을 지우면 선택이 해제된다(국가명·코드 비움, 위치 후보 비움).
- 선택 확정은 항목 클릭 또는 Enter뿐이다. 타이핑만 하고 목록 밖으로 나가면(blur) 선택된 국가가 있으면 그 국가명으로 입력값을 되돌리고, 없으면 입력 텍스트를 비운다(임의 텍스트가 국가로 남지 않음).
- 결과 없음: 목록 영역에 `일치하는 국가가 없습니다.`
- 선택 변경(다른 국가 선택·해제) 시 위치 후보 목록을 비운다(3-D, 3-F).

### 키보드

| 키 | 동작 |
| --- | --- |
| 아래/위 방향키 | 목록이 닫혀 있으면 열고 첫/마지막 항목 하이라이트. 열려 있으면 하이라이트 이동(끝에서 순환). 하이라이트 항목이 스크롤 영역 안에 보이게 한다 |
| Enter | 하이라이트 항목 선택 후 목록 닫음. 폼 제출은 막는다. 목록이 닫혀 있으면 평소처럼 제출 |
| Esc | 목록이 열려 있으면 목록만 닫고 전파를 막아 Dialog가 닫히지 않게 한다. 닫혀 있으면 기존 Dialog 닫기 |
| Tab | 목록을 닫고 다음 필드로 이동(하이라이트 항목은 선택하지 않음) |
| Home/End | 입력 안 커서 이동(기본 동작 유지) |

포커스는 항상 입력에 있고 하이라이트는 `aria-activedescendant`로 가리킨다.

### aria

- 입력: `role="combobox"`, `aria-expanded`, `aria-controls`(listbox id), `aria-autocomplete="list"`, `aria-activedescendant`(하이라이트 있을 때), 오류 시 `aria-invalid`/`aria-describedby`(기존 필드와 같은 `countryName-error` 패턴).
- 목록: `role="listbox"`, 항목 `role="option"` + 현재 선택 국가에 `aria-selected`.
- 후보 수 변화: 시각적으로 숨긴 `aria-live="polite"` 영역에 `N개 국가` / `일치하는 국가가 없습니다` 전달.
- 라벨은 `Label htmlFor`로 입력과 연결.

### 상태

| 상태 | 표현 |
| --- | --- |
| 기본(미선택) | 빈 입력, placeholder `국가명 또는 코드로 검색` |
| 목록 열림 | 입력 아래 `rounded-lg border border-gray-200 bg-white shadow-lg` 목록, 하이라이트 `bg-blue-50`, 선택된 항목 `font-medium` + 우측 체크(`lucide Check`) |
| 선택됨 | 입력값=국가명, 아래 `국가코드 KOR` |
| 오류(제출 시 미선택) | 기존 인라인 오류 패턴. 문구 `국가를 목록에서 선택해주세요` |
| 수정 모드, 코드가 목록에 있음 | 선택된 상태로 열림. 입력에는 `Intl` 이름이 보인다(기존 도시의 국가명이 달라도). 저장하면 `Intl` 이름으로 바뀜(N-1 영향) |
| 수정 모드, 코드가 목록에 없음(HKR·ZYC) | 미선택으로 열림(기존 값 유지 저장 없음, N-1). 입력 아래 안내 `기존 국가코드 HKR은(는) 목록에 없습니다. 국가를 다시 선택해주세요.`(`text-sm text-amber-800` + `Info` 아이콘). 선택 전 저장하면 위 미선택 오류가 나온다 |

## 3-C. 국가명 표시 (I-04, N-2)

- 국가명은 별도 입력칸 없이 국가 선택이 채운다. 요청 본문의 `countryName` = 선택한 항목의 국가명, `countryCode` = 항목의 alpha-3(대문자).
- 사용자가 국가명을 직접 수정해 저장하는 경로는 없다. 입력창 타이핑은 검색어일 뿐이고 선택 전에는 폼 값이 비어 있다.
- 읽기 전용 표시는 3-B의 `국가코드 KOR` 줄뿐이며, 국가명은 입력창 값으로 보인다.
- 수정 모드에서 국가를 다시 고르지 않아도 코드가 목록에 있으면 `Intl` 이름이 전송된다. 별도 안내 문구는 두지 않는다(N-1에서 사용자가 영향을 안내받고 확정).

## 3-D. 위치 찾기 버튼과 후보 목록 (I-06, N-3, N-4)

### 배치

국가코드 표시 줄 아래, 위도·경도 칸 위에 한 블록으로 둔다.

```
[ 위치 찾기 ]  (안내/비활성 사유 한 줄)
(상태 영역: 로딩 / 후보 목록 / 0건 / 오류 / 선택한 위치)
(후보가 표시된 동안만) 출처 표기 줄
위도 [        ]   경도 [        ]
```

- 버튼: `common/Button` `variant="secondary"` `size="sm"`, 아이콘 `lucide MapPin`, 라벨 `위치 찾기`. 요청 중에는 `isLoading` 스피너와 라벨 `찾는 중...`.
- 안내 한 줄(`text-sm text-gray-500`): 활성일 때 `위치 찾기로 좌표를 채우거나 아래에 직접 입력할 수 있습니다.` 비활성일 때는 아래 사유 문구로 대체한다.
- 모달 폭: 후보 행이 길어 `Dialog`에 `className="max-w-lg"`(512px)를 넘긴다. `Dialog` 기본 폭은 바꾸지 않는다.

### 비활성 조건과 사유 문구

버튼은 네이티브 `disabled`이고 사유 텍스트를 `aria-describedby`로 연결한다(2차의 비활성 버튼 방식과 동일). 사유는 우선순위 순으로 하나만 보인다.

| 조건 | 표시 |
| --- | --- |
| 도시명이 비어 있거나 공백뿐 | `도시명을 입력하면 위치를 찾을 수 있습니다.` |
| 국가 미선택 | `국가를 선택하면 위치를 찾을 수 있습니다.` |
| 요청 중 | 버튼 비활성, 안내 줄은 기본 안내 유지, 상태 영역에 로딩 문구 |
| 클릭 후 1초 쿨다운 | 버튼만 비활성, 문구 변화 없음(1초라 깜빡이지 않게) |
| 저장(제출) 중 | 버튼 비활성, 문구 변화 없음 |

쿨다운은 클릭 직후 1초 시작이다. 요청이 1초보다 오래 걸리면 요청 중 상태가 계속 비활성을 유지하고, 끝난 뒤 남은 쿨다운만큼만 더 비활성이다.

### 후보 목록

- 상태 영역은 버튼 줄 바로 아래이며 `aria-live="polite"`다(후보·로딩·0건·선택 확인 공용). 아무 것도 없으면 높이를 차지하지 않는다.
- 후보는 최대 5개(서버 상한). `ul` > `li` > `button type="button"` 행이다. 5개 이하라 listbox 패턴 없이 Tab/Enter/Space로 선택한다.
- 행 구성(2줄):
  - 1줄: 번호 + 표시명(예: `1. 서울특별시, 대한민국`), `text-sm font-medium text-gray-900`, 길면 `truncate` + `title`.
  - 2줄: `text-xs text-gray-500`에 행정구역 · 좌표(`37.5667, 126.9783`, 소수점 4자리). 행정구역은 서버가 내려 주는 값이 있을 때만 표시한다.
- 동일 표시명 구분: Paris+fr처럼 표시명이 같은 후보가 여럿이어도 2줄의 좌표(와 행정구역)로 구분한다. 번호는 중복 여부와 무관하게 모든 후보에 붙여 일관되게 한다.
- 행정구역을 응답에서 얻을 수 있는지는 확인되지 않았다(Q-4). 없으면 2줄은 좌표만 보이며 컴포넌트는 비어 있어도 깨지지 않아야 한다.
- 선택 시 동작:
  1. 위도·경도 칸에 후보 값을 서버 값 그대로 문자열로 채운다(예: `37.5666791`). 두 칸의 기존 검증 오류는 지운다.
  2. 후보 목록을 닫고 상태 영역에 `선택한 위치: 서울특별시, 대한민국`을 남긴다.
  3. 포커스를 위도 칸으로 옮긴다(수정 가능함을 알림).
- 수동 입력 유지: 선택 후에도 두 칸은 수정 가능하며, 사용자가 고친 값은 재검색 전까지 덮어쓰지 않는다. 위치 찾기 없이 직접 입력해 저장하는 흐름은 그대로다.
- 수정 모드: 기존 좌표는 후보를 고르기 전까지 바뀌지 않는다. 같은 버튼을 쓸 수 있다.
- 도시명 또는 국가가 바뀌면 후보 목록·`선택한 위치` 줄·오류·0건 문구를 비운다. 이미 채워진 위도·경도는 그대로 둔다.

### 출처 표기 (OpenStreetMap)

- 문구: `© OpenStreetMap 기여자`. 링크 `https://www.openstreetmap.org/copyright`를 건다(`target="_blank"` `rel="noopener noreferrer"`, 링크 텍스트는 `OpenStreetMap 기여자` 부분). 링크 주소는 OSM 저작권 안내 페이지로, 이 작업에서 열어 확인하지는 않았다(확인 필요).
- 표시 시점: 후보 목록이 보이는 동안(후보 행들 바로 아래). 후보 선택 후 목록이 닫히면 `선택한 위치: ...` 줄 끝에도 같은 표기를 붙여 좌표의 출처가 화면에 남게 한다. 로딩·0건·오류일 때는 후보 데이터가 없으므로 표시하지 않는다.
- 스타일: `text-xs text-gray-500`, 링크는 `underline hover:text-gray-700` + 기존 포커스 링(`focus-visible:ring-2 focus-visible:ring-blue-600`). 후보 행 안에는 넣지 않는다(행마다 반복 방지).
- aria: 텍스트 그대로 읽히는 일반 문단(`©`는 스크린 리더가 "저작권"으로 읽지만 의미가 전달됨). 별도 `aria-label`로 문구를 바꾸지 않는다. 새 창 링크이므로 링크에 `aria-label="OpenStreetMap 기여자 (새 창)"`를 둔다. 출처 줄은 live 영역 안에 있으므로 후보가 나올 때 함께 읽히지만 중복 낭독을 줄이려 `aria-live` 대상에서는 빼고 상태 영역 밖(후보 목록 아래 별도 `p`)에 둔다.
- 문구는 `cityErrorMessage.ts`의 위치 검색 묶음에 `attribution` 으로 둔다(3-E).

## 3-F. 인터랙션 규칙

1. 검색은 버튼 클릭에서만 시작한다. 입력·포커스·모달 열림에서는 호출하지 않는다(자동완성 금지 정책).
2. 요청 시작 시 이전 후보·상태 문구를 지우고 로딩 문구만 보인다. 요청 중에는 버튼이 비활성이다.
3. 모달이 닫히면(취소·Esc·배경 클릭·저장 성공) 진행 중 응답을 무시한다. 다시 열면 후보·상태·쿨다운이 초기 상태다. 저장 중에 도착한 응답은 버리고 위도·경도에 반영하지 않는다.
4. 응답 도착 시 요청 시점의 도시명·국가가 현재 값과 다르면 응답을 무시한다(후보를 보이지 않고 상태 영역도 비움).
5. 도시명 또는 국가 변경 시 후보·상태 문구를 비운다. 위도·경도 값은 건드리지 않는다.
6. 후보 선택·국가 목록 Enter는 폼을 제출하지 않는다.
7. 위치 찾기 실패·0건이어도 저장 흐름은 영향받지 않는다. 위도·경도 필수 검증은 그대로이며 수동 입력으로 저장할 수 있다.
8. 모달 포커스: 열릴 때 기존대로 도시명 입력. 국가 선택 후 포커스는 국가 입력에 남긴다(다음 Tab이 위치 찾기 버튼).
9. 세션 만료(401)는 기존 apiClient 흐름을 따른다.
10. 같은 도시명+국가로 다시 누르면 직전 결과를 재사용해 외부 호출을 줄이는 것을 권장한다(정책상 같은 질의 반복 차단 가능, 필수 아님. 재사용 시에도 1초 쿨다운과 로딩 표시는 동일하게 보여 동작이 일관되게 한다).

## 3-I. 접근성·반응형 요약

- 국가 선택: combobox/listbox/option, `aria-activedescendant`, Esc는 목록만 닫음, 후보 수 live 안내.
- 위치 찾기: 비활성 사유 `aria-describedby`, 상태 영역 `aria-live="polite"`(실패는 `role="alert"`), 후보 행은 버튼이라 Tab/Enter/Space 조작, 선택 후 포커스는 위도 칸, 출처 링크는 새 창 안내 `aria-label`.
- 포커스 링은 기존 `Input`/`Button`과 동일(`ring-blue-600`).
- 반응형: 최소 1024px 기준. 후보 행은 `truncate`, 모달 폭 `max-w-lg`. 모바일 대응 없음(프로젝트 규칙).
