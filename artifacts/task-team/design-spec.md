# T02 - 디자인 명세: 도시 관리 대시보드

기반 문서: `artifacts/task-team/requirements.md`

## 0. 사전 확인 사항

- `src/components/common/`: 아직 디렉터리 자체가 존재하지 않는다 (공용 컴포넌트 없음). 따라서
  이 문서의 인터랙티브 컴포넌트(모달/다이얼로그)는 **Radix UI primitive**로 구현 가능 여부를
  표기하며, 신규 공용 컴포넌트로 `src/components/common/`에 만들 것을 전제로 한다.
  - `package.json`에 `radix-ui`(또는 개별 `@radix-ui/react-*`) 의존성이 아직 없으므로,
    frontend-developer가 도입 여부를 확정해야 한다. Radix 도입이 어려우면 네이티브
    `<dialog>` 엘리먼트 + 포커스 트랩 직접 구현으로 대체 가능하다 (본 문서는 두 경우 모두
    동일한 상태/인터랙션 요구사항을 적용한다).
  - 버튼/인풋 등 프리미티브가 아닌 요소는 `class-variance-authority`(cva)로 변형을 관리하는
    신규 공용 컴포넌트(`Button`, `Input` 등)로 만들 것을 권장한다 (요구사항이 아닌 제안).
- 색상/폰트: 브랜드 토큰이 정의되어 있지 않으므로 특정 hex 값을 지정하지 않는다. 아래 명세는
  Tailwind v4 표준 팔레트(`gray-*`, `blue-*`, `red-*`, `green-*` 등)와 표준 스케일
  (`p-4`, `rounded-lg`, `text-sm` 등)만 사용한다고 가정하고, 실제 클래스 선택은
  frontend-developer가 `.claude/rules/tailwind.md`를 따라 확정한다.
- 반응형 기준: 데스크톱 우선(1024px 이상), 태블릿(768px~1023px)까지는 레이아웃이 깨지지
  않는 수준으로 대응 (요구사항 §5-4 기본값 채택). 모바일 전용 최적화는 범위 밖.

## 1. 전체 화면 구조

단일 페이지 대시보드: `/cities` (App Router 기준 `src/app/cities/page.tsx`).

```
┌─────────────────────────────────────────────────────────┐
│ PageHeader: "도시 관리"                [+ 도시 추가 버튼] │
├─────────────────────────────────────────────────────────┤
│ SearchInput (키워드 검색)                                 │
├─────────────────────────────────────────────────────────┤
│ CityListTable                                            │
│  - 헤더: 도시명 | 국가명 | 국가코드 | 위도 | 경도 | 작업   │
│  - 각 행: 데이터 + [수정] [삭제] 아이콘 버튼               │
│  - 상태: 로딩 / 에러 / 빈 목록(전체 빈 상태 vs 검색 결과   │
│    없음) / 정상 목록                                      │
└─────────────────────────────────────────────────────────┘

오버레이 (조건부 렌더링):
- CityFormModal (추가/수정 겸용, mode: 'create' | 'edit')
- DeleteConfirmDialog (삭제 확인)
- Toast/알림 영역 (성공/실패 피드백, 화면 우측 하단 또는 상단 고정)
```

레이아웃은 스크롤 가능한 단일 컬럼이며, 페이지네이션 없이 전체 목록을 표시한다 (요구사항 §5-3
기본값). 단, `CityListTable`은 향후 페이지네이션을 추가하기 쉽도록 목록 영역과
헤더/검색 영역을 컴포넌트로 분리해 둔다.

## 2. 컴포넌트 계층

```
CitiesPage (src/app/cities/page.tsx)
├── PageHeader
│   └── AddCityButton (Button 공용 컴포넌트 - 신규 제안, cva 기반)
├── SearchInput (Input 공용 컴포넌트 - 신규 제안)
├── CityListTable
│   ├── CityListTableHeader
│   ├── CityListRow (반복)
│   │   ├── EditButton (아이콘 버튼)
│   │   └── DeleteButton (아이콘 버튼)
│   ├── LoadingState (스켈레톤 또는 스피너)
│   ├── ErrorState (재시도 버튼 포함)
│   └── EmptyState (전체 빈 상태 / 검색 결과 없음 - 메시지만 분기)
├── CityFormModal (추가/수정 겸용)
│   ├── FormField x5 (도시명, 국가명, 국가코드, 위도, 경도)
│   │   └── FieldErrorMessage (필드별 인라인 에러)
│   ├── FormErrorBanner (제출 실패 시 폼 상단 배너 - 중복 도시명 등)
│   └── SubmitButton / CancelButton
├── DeleteConfirmDialog
│   ├── ConfirmButton
│   └── CancelButton
└── ToastRegion (성공/실패 알림)
```

**재사용/Radix 매핑**

| 컴포넌트 | 성격 | src/components/common/ 기존 여부 | 대체 방안 |
| --- | --- | --- | --- |
| CityFormModal | 모달 | 없음 | Radix `Dialog` primitive 기반 신규 공용 `Modal` 컴포넌트 제안, 또는 `<dialog>` + 포커스 트랩 |
| DeleteConfirmDialog | 확인 다이얼로그 | 없음 | Radix `AlertDialog` primitive 권장 (일반 `Dialog`보다 파괴적 액션에 적합한 기본 접근성 제공) |
| ToastRegion | 토스트/알림 | 없음 | Radix `Toast` primitive 기반 신규 공용 `Toast` 컴포넌트 제안 |
| SearchInput | 텍스트 입력 | 없음 | 네이티브 `<input type="text">` 기반, Radix 불필요 (신규 공용 `Input` 컴포넌트로 추상화 권장) |
| AddCityButton / SubmitButton / EditButton / DeleteButton | 버튼 | 없음 | 네이티브 `<button>` + cva 기반 신규 공용 `Button` 컴포넌트, Radix 불필요 |

> Radix 미도입 시에도 `Dialog`/`AlertDialog`/`Toast`는 각각 포커스 트랩, `role="alertdialog"`,
> `aria-live` 영역을 수동 구현해야 하며 접근성 요구사항(§6)은 동일하게 적용된다.

## 3. 컴포넌트별 상태 및 인터랙션

### 3.1 CityListTable

| 상태 | 트리거 | 표시 |
| --- | --- | --- |
| Loading | 최초 진입, 검색어 변경 직후 fetch 중 | 행 영역에 스켈레톤 또는 스피너 + "불러오는 중..." 텍스트 |
| Error | 목록 조회 API 실패 | "목록을 불러오지 못했습니다" 메시지 + [다시 시도] 버튼 |
| Empty (전체) | 검색어 없음 & 데이터 0건 | "등록된 도시가 없습니다" + [도시 추가] 유도 버튼 |
| Empty (검색 결과 없음) | 검색어 있음 & 결과 0건 | "'{검색어}'에 대한 검색 결과가 없습니다" |
| 정상 목록 | 데이터 1건 이상 | 표 형태, 각 행에 도시명/국가명/국가코드/위도/경도/작업(수정·삭제) 열 |

- 검색어 입력 → debounce(예: 300ms) 후 재조회 → Loading 상태로 전환 → 결과 반영.
- 수정/삭제 성공 시 목록은 로컬 상태(React Query 캐시) 갱신으로 즉시 반영, 별도
  전체 재조회 없이도 동작하되 실패 시(존재하지 않는 id 등) 최신 목록으로 강제 refetch.

### 3.2 SearchInput

- 상태: 기본 / 포커스 / 입력 중 / (검색어 있을 때) 클리어 버튼 노출.
- 인터랙션: 입력값 trim 후 빈 문자열이면 전체 목록 조회로 취급 (요구사항 F2).
  대소문자 구분 없이 부분 문자열 포함 검색 (요구사항 §5-5 기본값).
- 클리어 버튼(X 아이콘) 클릭 시 검색어 초기화 + 전체 목록 재조회.

### 3.3 CityFormModal (추가/수정 겸용)

- `mode='create'`: 제목 "도시 추가", 필드 초기값 빈 값, 제출 버튼 "추가".
- `mode='edit'`: 제목 "도시 수정", 필드 초기값 선택된 도시 데이터, 제출 버튼 "저장".
- 상태: 기본(입력 중) / 제출 중(버튼 비활성 + 로딩 인디케이터) / 필드별 검증 실패 /
  제출 실패(서버 거부, 예: 중복 도시명) / 제출 성공(모달 닫힘 + Toast).
- 인터랙션 흐름:
  1. [도시 추가] 또는 행의 [수정] 클릭 → 모달 오픈, 첫 입력 필드에 자동 포커스.
  2. 필드 입력 중 blur 또는 제출 시점에 유효성 검사 실행 (§4 참고).
  3. 제출 → 버튼 비활성화 + 로딩 표시 → 성공 시 모달 닫힘 + 목록 갱신 +
     성공 Toast("도시가 추가/수정되었습니다") → 실패 시 모달 유지, 입력값 보존,
     에러 메시지 표시 (필드별 또는 상단 배너, §4).
  4. 취소 버튼 또는 배경 클릭 또는 Esc 키 → 입력 중인 내용이 있으면 확인 없이 바로 닫음
     (요구사항에 별도 "변경사항 손실 확인" 요구 없음 → 단순 닫기로 처리, 필요 시 추후
     UX 결정 사항으로 별도 확인).

### 3.4 DeleteConfirmDialog

§5에서 상세.

### 3.5 ToastRegion

- 성공 케이스: 추가/수정/삭제 성공 시 각각 "도시가 추가되었습니다" / "도시가 수정되었습니다" /
  "도시가 삭제되었습니다".
- 실패 케이스: 목록 조회 실패는 인라인 ErrorState로 처리(토스트 아님). 추가/수정/삭제 실패는
  토스트 또는 폼 내 인라인 에러로 이중 처리하지 않고, **폼 관련 실패(중복 도시명 등)는 폼 내
  인라인 에러로만**, **삭제 실패(대상 없음 등) 및 수정 대상 없음 실패는 Toast + 목록
  자동 새로고침**으로 구분한다 (폼이 이미 닫혀 있는 삭제 케이스는 토스트가 유일한 피드백
  경로이므로).
- 자동 사라짐(예: 4초) + 수동 닫기(X) 아이콘 제공.

## 4. 도시 추가/수정 폼 필드 구성 및 유효성 검사 UX

| 필드 | 타입 | 필수 | 검증 규칙 | 에러 메시지 예 |
| --- | --- | --- | --- | --- |
| 도시명 (cityName) | text | O | 공백 제외 1자 이상 | "도시명을 입력해주세요" |
| 국가명 (countryName) | text | O | 공백 제외 1자 이상 | "국가명을 입력해주세요" |
| 국가코드 (countryCode) | text | O | ISO 3166-1 alpha-2 (영문 대문자 2자) | "국가코드는 영문 2자(예: KR)로 입력해주세요" |
| 위도 (lat) | number | O | 숫자 파싱 가능 & -90 ~ 90 | "위도는 -90~90 사이의 숫자여야 합니다" |
| 경도 (lng) | number | O | 숫자 파싱 가능 & -180 ~ 180 | "경도는 -180~180 사이의 숫자여야 합니다" |

**유효성 검사 UX 원칙**

- 필드별 에러는 해당 입력 요소 바로 아래에 인라인으로 표시한다 (`FieldErrorMessage`).
- 제출 시점에 전체 필드를 한 번에 검사해 모든 에러를 동시에 노출한다 (하나씩 순차 노출 X).
- 이미 에러가 표시된 필드는 값이 변경되는 즉시(onChange) 재검증해 에러를 즉시 해제할 수
  있게 한다 (제출 후에는 즉시 피드백, 최초 입력 중에는 blur 시점 검증으로 과도한 방해 방지).
- 서버 측에서만 판단 가능한 에러(중복 도시명 "이미 등록된 도시입니다", 수정 대상 없음)는
  필드 에러가 아닌 **폼 상단 배너(FormErrorBanner)**로 표시한다. 다만 중복 도시명 케이스는
  원인이 "도시명+국가명 조합"이므로 배너 문구에 두 필드명을 함께 안내한다
  (예: "이미 등록된 도시입니다 (도시명 + 국가명 중복)"), 필요 시 두 필드 테두리도 강조
  스타일(에러 색상)로 표시해 원인 필드를 시각적으로 지목한다.
- 제출 실패 시 입력값은 그대로 유지된다 (요구사항 F3/F4 수용 기준).
- 국가코드 형식 오류는 제출을 막는 검증 오류이나, 국기 매핑 실패(유효한 코드지만 아이콘
  없음)는 등록을 막지 않고 기본 아이콘/빈 국기로 대체한다 — 이 두 실패는 서로 다른 레이어임에
  유의 (형식 검증은 클라이언트 폼 단계, 국기 렌더링은 목록/폼 표시 단계).

## 5. 삭제 확인 플로우

1. 행의 [삭제] 아이콘 버튼 클릭 → 즉시 삭제하지 않고 `DeleteConfirmDialog` 오픈.
2. 다이얼로그 내용: "'{도시명}({국가명})'을(를) 삭제하시겠습니까? 이 작업은 되돌릴 수
   없습니다." + [취소] [삭제] 버튼. [삭제] 버튼은 파괴적 액션임을 시각적으로 구분
   (예: 위험 색상 계열 강조 - 정확한 색상 클래스는 frontend-developer가 팔레트 내에서 선택).
3. [삭제] 클릭 → 버튼 비활성화 + 로딩 표시 → 성공 시 다이얼로그 닫힘 + 목록에서 즉시 제거
   + 성공 Toast.
4. 실패 시(대상 없음 등) 다이얼로그를 닫고 Toast로 에러 표시 + 목록 자동 새로고침
   (요구사항 F5 수용 기준 - 다이얼로그를 계속 띄워봤자 대상이 이미 없으므로).
5. 중복 클릭/더블 삭제 방지: 삭제 요청 전송 중에는 [삭제] 버튼을 비활성화해 동일 다이얼로그
   내 중복 요청을 막는다. 두 번째 세션에서 이미 삭제된 경우의 오류 응답은 4번과 동일하게
   처리되어 최종적으로 목록에서 사라진 상태로 수렴한다.
6. 다이얼로그는 [취소], 배경 클릭, Esc 키로 닫을 수 있으며 이 경우 아무 요청도 보내지 않는다.

## 6. 접근성 및 반응형

### 접근성

- 모든 폼 필드는 `<label htmlFor>` 또는 Radix `Label`로 입력 요소와 명시적으로 연결한다.
- 아이콘 전용 버튼(수정/삭제/클리어/토스트 닫기)에는 `aria-label`을 명시한다
  (예: `aria-label="{도시명} 삭제"`).
- 모달/다이얼로그: 오픈 시 포커스가 다이얼로그 내부(첫 입력 필드 또는 기본 액션 버튼)로
  이동하고, 닫힘 시 트리거 요소로 포커스가 복귀한다. 배경 콘텐츠는 `aria-hidden` 처리하고
  포커스 트랩을 적용한다 (Radix `Dialog`/`AlertDialog` 사용 시 기본 제공).
- `DeleteConfirmDialog`는 `role="alertdialog"` 시맨틱을 사용한다 (Radix `AlertDialog`가
  기본 제공).
- 키보드 조작: Tab으로 모든 인터랙티브 요소 순회 가능, Enter로 폼 제출, Esc로 모달/다이얼로그
  닫기, 표 내 수정/삭제 버튼도 Tab 순서에 포함.
- 폼 에러 메시지는 해당 입력 요소와 `aria-describedby`로 연결하고, 유효하지 않은 필드는
  `aria-invalid="true"`를 설정한다.
- Toast 영역은 `aria-live="polite"` (또는 실패 토스트는 `assertive`)로 스크린리더에
  비동기 알림이 전달되도록 한다.
- 로딩 상태는 `aria-busy` 또는 스크린리더 전용 텍스트("불러오는 중")로 안내한다.

### 반응형

- 기준 해상도: 데스크톱 1024px 이상 (요구사항 §5-4 기본값).
- 태블릿(768px~1023px): `CityListTable`의 열 너비를 유연하게 축소하되 열 자체를 숨기지
  않는다. 필요 시 가로 스크롤(`overflow-x-auto`)을 표 컨테이너에 적용해 레이아웃 깨짐을
  방지한다. `CityFormModal`은 뷰포트 대비 폭을 백분율 기반으로 축소(`max-w-*` 유지)한다.
- 모바일(767px 이하) 전용 최적화는 범위 밖이나, 최소한 표가 컨테이너를 벗어나 페이지 전체
  가로 스크롤을 유발하지 않도록 표 컨테이너 스코프의 `overflow-x-auto`만 기본 적용해 둘
  것을 권장한다.
