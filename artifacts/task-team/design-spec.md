## 2. 결과 수 표시와 검색

### 2.1 결과 수 줄 (신규)

- 위치: `SearchInput` 줄 오른쪽 끝(`SearchInput`은 `max-w-sm` 유지, 같은 줄에서 양 끝 정렬). 1024px에서 한 줄에 들어간다.
- 문구(`text-sm text-gray-500`, 숫자는 천 단위 구분 쉼표):
  - 검색어 없음: `전체 3,791개` (2차: 서버 이름 접두사가 붙는다. 2-F 참조.)
  - 검색어 있음: `검색 결과 12개 / 전체 3,791개`
  - 검색 결과 0건: `검색 결과 0개 / 전체 3,791개` (표 안에는 기존 "'{검색어}'에 대한 검색 결과가 없습니다." 유지)
- 로딩 중·에러 상태에서는 결과 수 줄을 숨긴다(자리는 비워두지 않아도 됨).
- 접근성: 이 줄을 `aria-live="polite"`로 두어 필터링 결과를 스크린리더에 알린다. 20개 제한 안내는 B-1 결정으로 필요 없으므로 만들지 않는다.
- 도시 추가·삭제 직후 숫자가 목록 갱신과 함께 즉시 바뀐다.

### 2.2 검색 규칙

| 항목 | 규칙 |
| --- | --- |
| 입력 힌트 | placeholder `도시명 또는 국가명으로 검색`, 스크린리더 라벨 `도시 검색` 유지 |

- 폼 안에서 국기 미리보기는 추가하지 않는다(현재 없음).
- 목록: 국가코드 열은 `ARE`처럼 alpha-3를 그대로 표시한다. 도시명 앞 국기는 alpha-3로 계산한다. 63개 코드 전부 매핑(B-4)이 목표이며, 매핑에 없는 코드는 `🏳️`로 표시해 목록이 깨지지 않는다. 형식은 유효하지만 매핑에 없는 코드로도 등록은 막지 않는다(기존 원칙).
- 존재하지 않는 코드(예: `ZZZ`)를 클라이언트가 막을지는 서버 검증에 맡긴다. 서버가 거부하면 §5.2의 서버 메시지 배너로 표시한다. 서버 동작은 확인 필요.

## 4. 100자 제한 제거 (B-5)

- 도시명·국가명 입력의 `maxLength=100` 속성과 "~자 이하여야 합니다" 오류 문구를 제거한다.
- 검증은 필수 입력(공백 제외 1자 이상)만 남긴다. 오류 문구 `도시명을 입력해주세요`, `국가명을 입력해주세요` 유지.
- 서버가 길이 제한을 두면 400 메시지를 §5.2 방식으로 표시한다. 서버 제한 값은 확인 필요이므로 문서·UI에 숫자를 쓰지 않는다.
- 매우 긴 이름이 표에서 레이아웃을 깨지 않도록 도시명·국가명 셀은 줄바꿈 허용(`break-words`)으로 처리한다. 행 높이만 늘어난다.

### 5.1 클라이언트 중복 사전 검사 (B-6)

- 시점: 제출 시, 필드 검증이 모두 통과한 뒤 서버 요청 전에 실행. 요청은 보내지 않는다(제출 버튼은 눌렀다 바로 복귀, 로딩 표시 없음).
- 비교: 도시명+국가명 쌍, 앞뒤 공백 제거 후 대소문자 무시. 수정 모드는 편집 중인 도시 자신을 제외한다. 서버의 비교 기준(공백·대소문자)은 확인 필요이므로 클라이언트는 위 기준으로만 막고, 통과해도 서버가 거부하면 §5.2로 표시한다.
- 표시: 폼 상단 `FormErrorBanner`(기존 `role="alert"` 배너)에 `이미 등록된 도시입니다.`, 도시명·국가명 입력 두 개의 테두리를 오류 색으로 강조(현재 중복 처리 방식과 동일). 입력값은 보존된다. (2차: 중복 사전 검사 대상은 개발 탭 목록이다. 운영 탭은 쓰기 불가.)
- 목록을 아직 못 받았거나 조회 실패 상태이면 사전 검사를 건너뛰고 서버 판단에 맡긴다.
- 배너와 강조는 도시명 또는 국가명 입력이 바뀌면 해제하지 않아도 되며 다음 제출 시 다시 계산된다(현재 동작과 동일).

### 5.2 쓰기 실패 (추가·수정)

- 모달은 닫히지 않고 입력값을 전부 보존한다. 제출 버튼은 요청 종료 후 즉시 다시 활성화된다(재시도 가능). 모달 닫기(Esc, 배경, 취소)는 요청 중에는 막힌 현재 동작 유지.
- 표시 위치: 모두 폼 상단 `FormErrorBanner`. 필드 하단 인라인 오류는 클라이언트 검증 전용으로 유지한다.
- 서버 400 `{status:"fail", data:"메시지"}`: 메시지 문자열을 그대로 배너에 표시한다(가공하지 않음). 서버가 중복을 거부한 경우도 같은 방식이며 이때 도시명·국가명 강조는 메시지가 `이미 등록된 도시입니다.`와 같을 때만 적용한다. 서버 중복 응답의 상태 코드·문구는 확인 필요.
- 그 외 원인별 문구:

| 원인 | 배너 문구 |
| --- | --- |
| 네트워크 실패, 타임아웃 | `서버에 연결할 수 없습니다. 입력한 내용은 유지됩니다. 잠시 후 다시 시도해주세요.` |
| 서버 5xx | `서버에 문제가 발생했습니다. 입력한 내용은 유지됩니다. 잠시 후 다시 시도해주세요.` |
| 토큰 발급 실패, 재발급 후에도 401 | `서버 인증에 실패했습니다. 잠시 후 다시 시도하거나 관리자에게 문의해주세요.` |
| 서버 설정 오류(테스트 이메일 등 환경 변수 없음) | `서버 설정이 올바르지 않아 저장할 수 없습니다. 관리자에게 문의해주세요.` |
| 서버가 메시지 없이 4xx | `저장하지 못했습니다. 입력 내용을 확인해주세요.` |

- 토큰 값, 테스트 이메일, API 주소는 어떤 문구에도 넣지 않는다.
- 수정 대상이 서버에 없음: 현재 동작 유지(모달 닫기 + 토스트 `대상을 찾을 수 없습니다.` + 목록 재조회). 서버가 없는 id에 어떤 상태·메시지를 반환하는지 확인 필요이므로, 4xx 중 이 경우로 판별되는 기준은 T04에서 정한다. 판별되지 않으면 위 "메시지 없이 4xx" 또는 서버 메시지 배너로 처리한다.
- 배너 문구는 새 에러가 올 때 교체되며, 다음 제출 시작 시 지운다(현재 동작).

### 5.3 삭제 실패

모달 없이 토스트(`variant: "error"`)로 표시한다. 대상 없음일 때만 다이얼로그를 닫고 목록을 재조회하고, 그 외 원인은 다이얼로그를 열어 둔 채 재시도할 수 있게 한다(게이트 결정).

| 원인 | 토스트 제목 |
| --- | --- |
| 이미 삭제됨(대상 없음) | `대상을 찾을 수 없습니다.` (확인 필요: 서버의 없는 id 응답) |
| 네트워크 실패 | `서버에 연결할 수 없습니다. 잠시 후 다시 시도해주세요.` |
| 서버 5xx | `서버에 문제가 발생했습니다. 잠시 후 다시 시도해주세요.` |
| 토큰 발급 실패 | `서버 인증에 실패했습니다. 잠시 후 다시 시도하거나 관리자에게 문의해주세요.` |
| 서버 메시지가 있는 4xx | 서버 메시지 그대로 |

네트워크·5xx·인증·서버 설정 오류는 삭제 대상이 실제로 남아 있으므로 다이얼로그를 열어 둔다.

## 6. 접근성·반응형 변경분

- 결과 수 줄: `aria-live="polite"` (§2.1).
- 서버 오류 배너는 기존 `role="alert"` 유지.
- 반응형: 1024px 이상 기준 유지. 결과 수 줄은 좁은 폭(<768px)에서 검색창 아래 줄로 내려가도 된다(`flex-wrap`). 그 외 변경 없음.

## 7. 확인 필요 (서버 동작 미확인)

1. 중복 도시 추가 시 서버의 상태 코드·메시지 (§5.1, §5.2)
2. 없는 id 수정·삭제 시 서버의 상태 코드·메시지 (§5.2, §5.3)
3. 도시명·국가명 길이 제한 유무와 400 메시지 (§4)
4. 존재하지 않는 alpha-3 코드에 대한 서버 검증 여부 (§3)
5. 서버의 중복 비교 기준(공백·대소문자) (§5.1)
6. 3,791행 렌더링 실측 성능 (§1.1, T05 이후 판단)

# 2차: 운영·개발 탭

입력: `requirements.md`의 "2차: 운영·개발 서버 분리" (2-9 확정 결정 우선). 이 절은 2차로 달라지는 부분만 정의하며, 1차 본문과 충돌하면 이 절이 우선한다. 기술 구현 방식은 지정하지 않는다. 색은 현재 화면의 팔레트 클래스(`gray`, `blue`, `red`, `amber`)만 쓰고 새 토큰을 만들지 않는다.

## 2-E. 운영 탭: 쓰기 버튼 비활성과 안내

대상 버튼: 헤더 `도시 추가`, 행의 수정(연필)·삭제(휴지통) 아이콘 버튼. 빈 목록의 `도시 추가` 버튼은 아래 결정으로 제거한다.

- 비활성 표현: 기존 `Button`의 비활성 스타일(`disabled:opacity-40 disabled:pointer-events-none`)을 그대로 쓴다. 새 색·스타일 없음. 전부 `disabled`(네이티브)로 처리해 키보드 탭 순서에서 빠지고 클릭·Enter가 동작하지 않는다.
- 안내 문구 위치: 탭 목록 바로 아래, 검색 줄 위의 한 줄.
  - 스타일: `flex items-center gap-2 rounded-lg bg-amber-50 px-4 py-2 text-sm text-amber-800`, 왼쪽에 `Info`(lucide, `h-4 w-4`, `aria-hidden`) 아이콘. 개발 탭에서는 렌더하지 않는다(자리도 비운다).
  - 문구: `운영 서버는 쓰기 인증 준비 전이라 조회만 할 수 있습니다.`
- 접근성
  - 안내 줄에 고정 `id`를 주고, 헤더 `도시 추가` 버튼과 행의 수정·삭제 버튼에 `aria-describedby`로 연결한다. 이렇게 하면 스크린리더가 버튼에 도달할 때 비활성 사유를 읽는다.
  - 네이티브 `disabled`는 포커스를 받지 못하므로 스크린리더의 가상 커서(탐색 모드)로 읽는 경로가 사유 전달 수단이다. 키보드 포커스로도 사유를 알리려면 `aria-disabled`(포커스 가능, 클릭 무시) 방식이 필요하나, 현재 `Button` 공용 컴포넌트에 없는 동작이라 이번엔 네이티브 `disabled` + `aria-describedby` + 보이는 안내 줄로 정한다. 변경 필요 시 사용자 결정 항목에 둔다(2-I 1번).
  - 안내 줄은 탭 전환 시 나타나고 사라진다. 전환 자체를 알리기 위해 `role`/`aria-live`는 달지 않는다(탭 선택 변경과 패널 내용이 이미 전달됨).
- 툴팁(hover 안내)은 추가하지 않는다. 비활성 버튼은 포인터 이벤트가 없어 동작하지 않으며, 보이는 안내 줄로 충분하다.
- 빈 목록 상태(두 탭 공통): 빈 목록 안내 속 `도시 추가` 버튼과 `CityListTable`의 `onAddCity` prop을 제거하고 문구만 표시한다. 헤더 버튼과 같은 `openAddModal`을 호출하는 중복 버튼이라 사용자 결정으로 삭제(1차 §2 빈 상태 버튼 대체).

## 2-F. 현재 서버 오인 방지 표시

| 위치 | 표시 |
| --- | --- |
| 탭 | 선택된 탭 라벨 + 밑줄(2-D) |
| 목록 헤더 건수 줄 (1차 §2.1) | 서버 이름을 앞에 붙인다. 검색어 없음: `운영 서버 전체 4,204개` / `개발 서버 전체 3,791개`. 검색어 있음: `운영 서버 검색 결과 12개 / 전체 4,204개`. 0건: `운영 서버 검색 결과 0개 / 전체 4,204개`. 숫자는 천 단위 쉼표, 스타일 1차 그대로(`text-sm text-gray-500`, `aria-live="polite"`) |
| 표 안 문구 | 로딩 `운영 서버 목록을 불러오는 중...`, 빈 목록 `운영 서버에 등록된 도시가 없습니다.`, 검색 0건 `운영 서버에서 '{검색어}'에 대한 검색 결과가 없습니다.` (서버 이름 `운영`/`개발`로 치환) |
| 추가·수정 모달 제목 | `[개발] 도시 추가` / `[개발] 도시 수정` (사용자 결정: 앞 접두어). 운영은 쓰기 불가이므로 모달은 개발에서만 열린다 |
| 삭제 확인 다이얼로그 | 제목 `[개발] 도시 삭제`. 본문 첫머리에 `개발 서버에서` 를 넣어 `개발 서버에서 '{도시명}'을(를) 삭제하시겠습니까?` 형태로 쓴다(기존 본문 문구는 구현에서 확인해 같은 구조로 앞에 붙임) |
| 성공 토스트 | `개발 서버에 도시가 추가되었습니다` / `개발 서버의 도시가 수정되었습니다` / `개발 서버에서 도시가 삭제되었습니다` |
| 오류 메시지 | 모달 배너·삭제 토스트의 1차 §5.2/§5.3 문구는 그대로 두되 대상 서버는 모달 제목과 다이얼로그에서 이미 식별되므로 접두사를 추가하지 않는다. 단 서버 설정 오류 문구는 아래 2-G를 따른다 |

서버 이름 접두사의 시각 구분은 텍스트로만 한다(배지·색 구분 추가 없음).

## 2-G. 탭별 상태 (로딩·오류·설정 오류)

각 탭의 상태는 독립이다. 한 탭이 오류여도 다른 탭 전환·표시는 정상이다. 상태는 표 컨테이너 안에 1차 구조 그대로 표시한다.

| 상태 | 표시 |
| --- | --- |
| 로딩 (해당 탭 최초 조회) | `{서버} 서버 목록을 불러오는 중...` (1차 `불러오는 중...`에 서버 이름 추가). 건수 줄 숨김 |
| 이미 받은 탭으로 복귀 | 캐시된 목록을 즉시 표시. 재조회가 일어나도 `불러오는 중...`으로 바꾸지 않고 기존 행 유지(1차 §5.0 "쓰기 후 갱신" 규칙과 동일) |
| 탭 전환 중 이전 탭 응답 | 현재 탭 표시에 영향 없음(캐시가 탭별 분리) |
| 일반 오류 (네트워크·5xx 등) | 1차 §5.0 사유 문구 앞에 서버 이름 한 줄을 붙인다. 예: `운영 서버: 서버에 연결할 수 없습니다. 네트워크 상태를 확인한 뒤 다시 시도해주세요.` + `다시 시도` 버튼(해당 탭만 재조회) |
| 설정 오류 (해당 서버의 주소 환경 변수 누락·오류) | 같은 오류 구조(아이콘+문구+`다시 시도`)로 `{서버} 서버 설정이 올바르지 않아 목록을 불러올 수 없습니다. 관리자에게 문의해주세요.` 환경 변수 이름·주소·토큰은 문구에 넣지 않는다. 건수 줄 숨김 |
| 개발 쓰기 설정 오류 (테스트 이메일 누락 등) | 조회는 정상이므로 목록은 그대로. 쓰기 시도 시 1차 §5.2 `서버 설정이 올바르지 않아 저장할 수 없습니다. 관리자에게 문의해주세요.` 배너를 모달에 표시 |
| 운영 쓰기 서버 거부 (우회 호출) | UI에서는 발생하지 않는다. 표시 문구는 운영 쓰기 안내 문구와 동일 |
| 두 탭 모두 설정 오류 | 각 탭에서 위 설정 오류 표시. 앱은 정상 렌더 |

설정 오류 문구는 `src/utils/cityErrorMessage.ts`에서 서버 이름을 받아 만든다(1차 원칙: 문구는 한곳에서).

## 2-H. 상태 전환 요약

1. 진입: 운영 탭 선택, 검색어 빈 값, 운영 목록 조회 시작. 개발 탭은 선택 전까지 조회하지 않아도 된다(조회 시점은 구현 결정).
2. 탭 전환: 선택 탭 변경, 안내 줄 표시/해제, 쓰기 버튼 활성/비활성 변경, 검색어 유지, 스크롤은 맨 위로(서버가 바뀌면 목록 자체가 다르므로 1차 "검색어 바뀌면 맨 위"와 같은 이유).
3. 모달 열림: 탭 전환 불가. 닫히면 다시 가능.
4. 모달 안에서 쓰는 서버는 항상 열 때의 탭이다(운영에서는 열 수 없음).

## 2-I. 접근성·반응형 요약, 확인 필요

- 접근성: 탭 `tablist/tab/tabpanel`, 방향키·Home/End, 선택 상태 `aria-selected`, 비활성 버튼은 `aria-describedby`로 안내 줄 연결, 건수 줄 `aria-live="polite"`, 안내 줄에 live 속성 없음. 포커스 링은 기존과 동일.
- 반응형: 1024px 이상 기준. 탭 목록은 왼쪽 정렬, 안내 줄은 폭이 좁으면 줄바꿈. 그 외 변경 없음.
- 사용자 결정 (2026-11-09)
  1. 비활성 버튼: 네이티브 `disabled` + `aria-describedby` + 보이는 안내 줄. `Button` 변경 없음.
  2. 모달·삭제 다이얼로그 제목: 앞 접두어 `[개발] `. 삭제 본문의 현재 문장은 구현 단계에서 `DeleteConfirmDialog.tsx`로 확인한다.
  3. 빈 목록의 `도시 추가` 버튼: 두 탭 모두에서 제거.
- 구현 판단으로 남김
  1. 개발 탭을 선택하기 전에 개발 목록을 미리 조회할지(성능·서버 부하 판단, 요구사항 2-5에서 구현 결정으로 남김).
